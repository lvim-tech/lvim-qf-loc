1. INTRODUCTION                                           *lvim-qf-loc-intro*

lvim-qf-loc improves Neovim's quickfix and location lists. Besides the floating
tabbed popup (browse / delete / persist lists, and load diagnostics into the
quickfix), it provides a full quickfix workflow that REPLACES nvim-bqf and
quicker.nvim with a single, self-contained module:

  - a floating PREVIEW of the entry under the cursor,
  - an EDITABLE quickfix whose `:w` writes back to the files,
  - CONTEXT expand/collapse around each entry, and
  - a BROWSER hosted in the lvim-utils area.

It is crash-safe by design: no LuaJIT FFI, no "magicwin" scroll math (nvim-bqf),
and no delimiter parsing (quicker) — the editable text is the source line and
the location prefix is virtual text, entry identity rides on extmarks, and every
write is verified against the file before it is applied.

==============================================================================
2. REQUIREMENTS                                    *lvim-qf-loc-requirements*

  - Neovim 0.10+.
  - lvim-ui (optional) — enables the tabbed management popup.
  - lvim-picker (optional) — enables the "area" view and the browser.
    The native view works without either.

Disable nvim-bqf and quicker.nvim: this plugin owns 'quickfixtextfunc' and the
quickfix window, and the three would conflict. See |lvim-qf-loc-health|.

==============================================================================
3. COMMANDS                                            *lvim-qf-loc-commands*

                                                                      *:LvimQf*
:LvimQf [subcommand]    Quickfix command. With no subcommand the management
                        popup opens on the Browse tab. Subcommands
                        (tab-completed):

                          open         open the quickfix window (`:copen`)
                          close        close it (`:cclose`)
                          next         next quickfix list (`:cnewer`)
                          prev         previous quickfix list (`:colder`)
                          diagnostics  load diagnostics into a list + browse
                          browse       popup on the Browse tab
                          delete       popup on the Delete tab
                          storage      popup on the Storage tab

                                                                     *:LvimLoc*
:LvimLoc [subcommand]   As above for the current window's location list, WITHOUT
                        `diagnostics` (location lists carry no diagnostics).
                        `open`/`close`/`next`/`prev` map to
                        `:lopen`/`:lclose`/`:lnewer`/`:lolder`.

==============================================================================
4. VIEWS                                                  *lvim-qf-loc-views*

`config.view` selects the SINGLE UI the quickfix opens in, so `:copen` and the
list always look the same — no two competing UIs.

  "native"  (default)   The native quickfix window: editable source lines
                        (|lvim-qf-loc-editable|), context expand/collapse
                        (|lvim-qf-loc-context|) and a floating preview
                        (|lvim-qf-loc-preview|).

  "area"                `:copen` opens the browser (|lvim-qf-loc-browser|) in
                        the lvim-utils area instead of the native window.

`:LvimQf browse` opens the area browser explicitly in either view.

==============================================================================
5. EDITABLE QUICKFIX                                   *lvim-qf-loc-editable*

In the native view each quickfix row shows its file's SOURCE LINE, editable;
the `file:lnum` prefix is virtual text and cannot be broken by an edit. Edit any
rows and `:w` to apply the changes to the files.

Open keys inside the quickfix window (see `config.edit.keys`):

  <CR>     open the entry in the window the quickfix was called from
  <C-v>    open in a vertical split
  <C-x>    open in a horizontal split
  <C-t>    open in a new tab
  g?       show the keymap cheatsheet

Safety: a line is written only when the file's current text still equals what
was shown (an external change is skipped, never clobbered); conflicting edits to
one line are reported; one row maps to one source line (no line-count drift);
every file operation is guarded.

`config.edit.autosave` controls saving the touched files:
  "unmodified"  (default)  save files that were not already modified.
  true                     always save.
  false                    never save (leave the buffers modified).

==============================================================================
6. CONTEXT                                              *lvim-qf-loc-context*

In the quickfix window (see `config.context.keys`):

  zo       Expand: add `config.context.before`/`after` source lines around each
           entry as dim context rows. Repeat to add more.
  zc       Collapse: keep only the real entries.

`config.context.dim_amount` (0..1) sets how strongly the context rows are dimmed
(0 = full syntax colour, 1 = invisible).

Context rows are sourced live from the buffer, so they read (and edit) exactly
like the real lines. `:cnext`/`:cprev` skip them.

==============================================================================
7. PREVIEW                                              *lvim-qf-loc-preview*

In the native view a single floating window above the quickfix shows the REAL
file buffer of the entry under the cursor (live syntax), scrolled to the entry
with its line highlighted; it follows the cursor and closes with the list. It
uses only public window APIs — no FFI, no scroll math.

`config.preview.scroll_down`/`scroll_up` (default `<C-d>`/`<C-u>`) scroll the
preview a half-page from the list; `config.preview.position`
("auto"|"always"|"never") controls whether the title shows `line N │ col M`.
Disable the preview with `config.preview.enabled = false`.

==============================================================================
8. BROWSER                                              *lvim-qf-loc-browser*

`:LvimQf browse` (and `:LvimLoc browse`) opens the list in the lvim-utils area:
the list + a real-Neovim preview, with fuzzy narrowing, the mark dot, `<C-q>` →
a new list, and (for diagnostic lists) a severity filter bar. `config.browser`
sets the layout, the preview side (`<C-n>`/`<C-p>` rotate it live) and the
per-severity icons.

The Browse tab of the management popup lists every stored list; pick one to
switch to it and open its entries in the browser.

The browser is the ONLY dockable UI here. `config.dock.dock_stack` (default
`true`) routes it through the lvim-utils dock STACK — a managed consumer, cyclable
with `<Leader>n`/`<Leader>p`/`<Leader>x`/`<Leader>m` and `:LvimDock`, one visible
per layout with no overlap. Set it `false` for a geometry-only standalone open
(still centrally sized, just not registered in the stack). `config.dock.force`
supplies per-layout ANCHORED geometry overrides, deep-merged per field over the
global
`lvim-utils.config.dock.geometry.<layout>`; an empty `{}` inherits the global.
Each layout may carry `height`, `height_auto`, `backdrop`, `auto_hide`,
`keep_focus`; `float` may ALSO carry `width`/`width_auto` — `area` and `bottom`
are always full-width. Both apply ONLY to the browser; the native quickfix window
and the cursor-preview float are content-fit and are NEVER dock consumers.

9. CONFIGURATION                                        *lvim-qf-loc-config*
>lua
  require("lvim-qf-loc").setup({
      notify = true,
      title_pos = "center",            -- browser + management-popup border-title
                                       -- alignment: "left" | "center" | "right"
                                       -- (layout-independent; the title TEXT stays
                                       -- dynamic: "Quickfix" / "Location List")
      cfilter = true,                  -- packadd :Cfilter / :Lfilter on setup
      view = "native",                 -- "native" | "area"

      -- dock routing for the area browser (native qf + preview float are
      -- content-fit and never dock consumers):
      dock = {
          dock_stack = true,           -- true = managed stack | false = standalone
          -- per-layout ANCHORED geometry overrides for the browser, deep-merged
          -- over the global lvim-utils dock geometry; empty {} inherits it. float
          -- may also carry width/width_auto; area/bottom are always full-width.
          force = { float = {}, area = {}, bottom = {} },
      },

      preview = {                      -- (native view) floating preview
          enabled = true,
          max_height = 15,
          border = { "", " ", "", "", "", "", "", "" },
          hl = "Visual",
          position = "auto",           -- "auto" | "always" | "never"
          scroll_down = "<C-d>",
          scroll_up = "<C-u>",
      },

      edit = {                         -- editable quickfix
          enabled = true,
          autosave = "unmodified",     -- "unmodified" | true | false
          separator = "│",
          max_filename_width = 40,
          syntax = true,
          keys = {
              open = "<CR>",
              vsplit = "<C-v>",
              split = "<C-x>",
              tab = "<C-t>",
              help = "g?",
          },
      },

      context = {                      -- expand/collapse context
          before = 3,
          after = 3,
          dim_amount = 0.4,
          keys = { expand = "zo", collapse = "zc", toggle = "" },
      },

      browser = {                      -- the area browser (slot height is central, no size here)
          layout = "area",
          preview_side = "above",      -- "above" | "below" | "right" | "left"
          icons = { E = "󰅚 ", W = "󰀪 ", I = " ", N = " ", H = " ", default = " " },
      },
  })
<
User options are merged in place into the live config, so any module reading
`require("lvim-qf-loc.config")` sees the effective values.

==============================================================================
10. HEALTH                                              *lvim-qf-loc-health*

`:checkhealth lvim-qf-loc` reports the Neovim version, whether lvim-picker is
present (for the area view / browser), the effective `view`, and warns if
another plugin (nvim-bqf / quicker.nvim) owns 'quickfixtextfunc' or is still
loaded — the one real source of conflicts.
